需要处理的边界问题

535 字节 VTP 将 NumberOfPoints 声明为 2147483648。导入触发 Windows Job 的内存分配限额，由保护程序终止（退出码 222），没有返回正式导入失败信号。记录的实际内存峰值仅数 MiB，说明这是超限分配请求被拒绝，不能描述成已经消耗了 6 GiB。未在无保护条件下运行，未推断其最终行为。

复现文件：tests/import_stress/fixtures/oversized-declared-count.vtp；清单：由 boundary/supplements 阶段生成的测试清单；记录：results.jsonl 中 oversized-declared-count 记录。建议在 VTK 分配前增加输入规模与资源预算检查，并验证分配失败可返回可恢复错误。本次仅测试，未修改业务代码。

范围与解释

  • 压力计时从正式服务 started 到 loaded，包含读取、验证、边界提取与共享边构建；不包含渲染。
  • 样例单位 MB/GB 使用十进制字节；内存 MiB/GiB 使用二进制。文件校验和已提前读取文件，不能把这些耗时当作冷缓存结果。
  • pass 表示符合该用例的预期；预期拒绝的损坏文件被拒绝也算通过。标为 observe 的路径及格式策略仅记录行为，不能据此宣称支持。
  • 文件体积上限测试使用合成三角形表面网格；不能推断任意体网格、CGNS 或压缩数据有相同上限。
  • 子进程私有提交上限为 6 GiB，并保留至少 1.5 GiB 系统物理内存及 2 GiB 提交余量；resource_limited 是测试保护阈值，不是应用硬上限。
  • 已知行为：emoji 路径不支持；已测 259 字符路径可用，260/261/280/400 字符被拒绝；PolyData 改为 .vtu 仍会按内容接受。
  • 缺少匹配 Release 依赖，本次仅验证 Debug。未模拟网络盘断连、物理磁盘 I/O 故障，未覆盖全部文件编码和任意格式组合。
  • 测试中的取消通过服务 API；并不表示界面具有取消按钮。销毁活动导入测试覆盖服务析构，不等同于完整应用退出验收。
  • “排队期间文件变化”在目标文件开始读取前执行；未宣称覆盖读取过程中所有并发修改时序。
  • 共线的零面积三角形被接受；这里仅记录当前行为，没有预设几何质量验收规则。
